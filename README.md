# trainer_backend — API сервиса персональных тренировок

Spring Boot на Kotlin: расписание, чат, дневники тренировок, программы, чек-ины с фото,
видеоразбор техники, вход и сессии. Обслуживает мобильный клиент
[trainer_app_mobile](https://github.com/rollstain/trainer_app_mobile), прод — `https://api.lyashukfit.ru`.

## Стек

- **Kotlin 2.3**, **Spring Boot 3.5**, JDK 17
- **Postgres 16**, JPA с `ddl-auto: validate` — схему ведёт только Flyway
- **Spring Security** + OAuth2 Resource Server, JWT на HS256
- **WebSocket** для чата, **springdoc-openapi** для описания ручек
- **AWS SDK S3** для медиафайлов, **Firebase Admin** для пушей
- **detekt** со своим конфигом `config/detekt.yml`

## Как устроен код

Пакеты по предметным областям, внутри каждого — один слой на файл:
`*Controller` → `*Service` → `*Repositories` → `*Entities`, DTO рядом. Контроллер не ходит
в репозиторий мимо сервиса, сервис не возвращает наружу entity.

## Запуск локально

Нужны JDK 17 и Docker для базы.

```bash
docker compose up -d postgres
JWT_SECRET=$(head -c 48 /dev/urandom | base64) ./gradlew bootRun
```

Приложение поднимется на `http://localhost:8080`, описание ручек — на `/swagger-ui.html`.
Flyway накатит миграции сам. Без `JWT_SECRET` длиной от 32 символов контекст не стартует —
это намеренно, чтобы прод не поднялся с пустым ключом.

Мобильному клиенту в эмуляторе бэкенд виден как `http://10.0.2.2:8080/`, см. README приложения.

### Переменные окружения

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `DB_URL`, `DB_USER`, `DB_PASSWORD` | подключение к Postgres | локальный `trainer` |
| `JWT_SECRET` | подпись токенов, от 32 символов | нет, обязательна |
| `TRAINER_ADMIN_TOKEN` | доступ к `/admin/**` | нет |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` | письма | пусто, ручки отвечают 501 |
| `TELEGRAM_BOT_USERNAME`, `TELEGRAM_BOT_SECRET` | вход через Telegram | пусто, кнопка скрыта |
| `VK_CLIENT_ID`, `APPLE_CLIENT_ID`, `GOOGLE_CLIENT_ID` | соцвход | пусто, провайдеры скрыты |
| `LEGAL_OPERATOR_NAME`, `LEGAL_OPERATOR_CONTACT` | реквизиты в правовых текстах | пусто |

Полный список — в `src/main/resources/application.yml`, значения по умолчанию видны там же.

## Проверки

```bash
./gradlew detekt                   # статический анализ
./gradlew test                     # юнит-тесты, база не нужна
./gradlew bootJar                  # артефакт build/libs/trainer-backend-<версия>.jar
python3 scripts/check_migrations.py # миграция не занимает имя, которое уже занято
```

Тесты — чистые юнит-тесты сервисов: контекст Spring не поднимается, Postgres не требуется.
Прогон занимает около двух минут вместе со сборкой.

## Миграции

Только Flyway, `src/main/resources/db/migration`, имена `V<номер>__<что делает>.sql`.
Номер не переиспользуется и не вставляется в середину: применённые миграции Flyway не пересчитывает.

`scripts/check_migrations.py` ловит попытку создать таблицу или индекс с уже занятым именем —
такая ошибка дважды роняла прод, поэтому проверка стоит в CI до сборки.

Откат выкатки возвращает предыдущий jar, но **не отменяет миграции**: схема откатывается только
из дампа, который снимает деплой перед выкладкой. Поэтому миграция обязана быть совместимой
с предыдущей версией кода — сначала добавляем, потом переключаем чтение, удаляем следующим релизом.

## Автоматика

| Workflow | Когда | Что делает |
|---|---|---|
| `ci.yml` | push и PR в `main` | проверка миграций, detekt, тесты, `bootJar`, обзор зависимостей на PR |
| `release.yml` | тег `v*` | собирает jar, создаёт GitHub Release со списком изменений от прошлого тега |
| `deploy.yml` | кнопка в Actions | выкатывает выбранный тег или ветку на прод: бэкап базы, замена jar, рестарт, проверка живости, автооткат |

Порядок выкатки и что настроить в секретах — `docs/deploy.md`.
